1. Deploy and Manage Microsoft 365 Tenant (25-30%)

▼ Implement and Manage a Microsoft 365 Tenant

🏢 Create a Tenant

  • Tenant: Dedicated instance of Microsoft 365 services
  • Initial domain: yourcompany.onmicrosoft.com
  • Key steps: Sign up, choose plan, set up admin account
  • Trial options: 30-day free trials available for most services
💡 Tip: The .onmicrosoft.com domain cannot be changed or deleted once created

🌐 Implement and Manage Domains

  • Add custom domains: Add your company domain (e.g., contoso.com)
  • DNS verification: Add TXT or MX record to verify ownership
  • DNS records required:
    • MX record - Email routing
    • CNAME records - Exchange Autodiscover, Teams, Intune
    • TXT records - SPF for email security
    • SRV records - Skype for Business/Teams
  • Set default domain: Users created after this use the default domain
# PowerShell: Add domain New-MsolDomain -Name "contoso.com" # Verify domain Confirm-MsolDomain -DomainName "contoso.com" # Set as default Set-MsolDomain -Name "contoso.com" -IsDefault

▼ Manage Users and Groups

👥 Create and Manage Users

  • Internal users: Regular organization members
  • External users (Guests):
    • B2B collaboration
    • Limited access to resources
    • Azure AD B2B features
  • User properties: Display name, UPN, licenses, location
  • Deletion: 30-day soft delete before permanent removal
# Create user New-MgUser -DisplayName "John Doe" -UserPrincipalName "john@contoso.com" ` -MailNickname "john" -PasswordProfile @{Password="TempPass123!"} # Bulk import from CSV Import-Csv "users.csv" | ForEach-Object { New-MgUser -DisplayName $_.DisplayName -UserPrincipalName $_.UPN ... }

📇 Manage Contacts

  • Mail contacts: External email addresses in GAL
  • Use cases: Partners, vendors, external collaborators
  • Visible in: Global Address List
  • No license required

👫 Create and Manage Groups

  • Microsoft 365 Groups:
    • Shared mailbox, calendar, SharePoint site, Planner, Teams
    • Dynamic membership based on user attributes
    • Naming policies and expiration
  • Security Groups:
    • Used for permissions and access control
    • Can be mail-enabled
    • Dynamic or assigned membership
  • Distribution Groups:
    • Email distribution lists only
    • No modern features
  • Shared Mailboxes:
    • Multiple users access same mailbox
    • Up to 50GB free (no license needed)
    • No sign-in capability
# Create Microsoft 365 Group New-UnifiedGroup -DisplayName "Marketing Team" -Alias "marketing" ` -EmailAddresses "marketing@contoso.com" # Create security group New-MgGroup -DisplayName "IT Admins" -MailEnabled:$false ` -SecurityEnabled:$true -MailNickname "itadmins"

📜 Manage Licenses

  • License types: Microsoft 365 E3, E5, F3, Business Premium, etc.
  • Service plans: Individual services within a license
  • Group-based licensing:
    • Assign licenses to groups
    • Automatic assignment to group members
    • Inherited licenses
  • License requirements: Ensure sufficient licenses available
# Assign license to user Set-MgUserLicense -UserId "john@contoso.com" ` -AddLicenses @{SkuId = "GUID-OF-LICENSE"} -RemoveLicenses @() # Group-based licensing New-MgGroupLicenseAssignment -GroupId "group-id" -SkuId "license-sku-id"

▼ Manage Roles and Role Groups

👑 Microsoft 365 and Microsoft Entra Roles

  • Global Administrator: Full access to all services
  • User Administrator: Manage users and groups
  • Exchange Administrator: Manage Exchange Online
  • SharePoint Administrator: Manage SharePoint
  • Teams Administrator: Manage Microsoft Teams
  • Security Administrator: Manage security settings
  • Compliance Administrator: Manage compliance features
  • Helpdesk Administrator: Reset passwords, limited admin
⚠️ Best Practice: Use least privilege principle - assign minimum permissions needed

🛡️ Role Groups in Defender XDR, Purview, and Workloads

  • Defender XDR roles:
    • Security Reader
    • Security Operator
    • Security Administrator
  • Purview roles:
    • Compliance Administrator
    • eDiscovery Manager
    • Insider Risk Management
  • Workload-specific roles: Exchange, SharePoint, Teams roles

🏗️ Administrative Units

  • Purpose: Delegate administration for specific organizational units
  • Scope: Limit admin permissions to subset of users/groups
  • Use case: Geographic or departmental delegation
  • Members: Users, groups, devices
# Create administrative unit New-MgDirectoryAdministrativeUnit -DisplayName "North America" ` -Description "Users in North America region" # Add members New-MgDirectoryAdministrativeUnitMemberByRef -AdministrativeUnitId $id ` -OdataId "https://graph.microsoft.com/v1.0/users/$userId"

🔐 Microsoft Entra Privileged Identity Management (PIM)

  • Just-in-time access: Activate roles when needed
  • Time-bound access: Roles expire automatically
  • Approval workflow: Require approval for role activation
  • MFA enforcement: Require MFA to activate roles
  • Access reviews: Periodic review of role assignments
  • Audit logs: Track role activations and usage
💡 Key Benefit: Reduces standing admin access and improves security posture

2. Implement and Manage Microsoft Entra Identity and Access (25-30%)

▼ Identity Synchronization

🔄 Prepare for Identity Synchronization

  • IdFix tool:
    • Identifies and fixes directory synchronization errors
    • Checks for duplicate proxyAddresses
    • Validates UPN formats
    • Finds invalid characters in attributes
  • Prerequisites:
    • Windows Server with AD DS
    • .NET Framework 4.7.2 or higher
    • SQL Server (Express or full)
    • Outbound internet connectivity
  • UPN considerations: Must match routable domain
📥 Download IdFix: https://microsoft.github.io/idfix/

🔗 Microsoft Entra Connect Sync

  • Features:
    • Password Hash Synchronization (PHS)
    • Pass-through Authentication (PTA)
    • Federation integration (AD FS)
    • Hybrid Azure AD join
    • Device writeback
  • Sync components:
    • Sync engine
    • Connector space
    • Metaverse
    • Synchronization Rules
  • Sync cycle: Every 30 minutes by default
  • Filtering: Domain-based, OU-based, attribute-based
# Force sync cycle Start-ADSyncSyncCycle -PolicyType Delta # Initial sync Start-ADSyncSyncCycle -PolicyType Initial # Check sync status Get-ADSyncScheduler

☁️ Microsoft Entra Cloud Sync

  • Lightweight agent: Installed on domain-joined server
  • Benefits:
    • High availability (multiple agents)
    • Cloud-based configuration
    • Simpler setup than Connect Sync
    • Better for multi-forest scenarios
  • Limitations:
    • Fewer features than Connect Sync
    • No device sync
    • No group writeback
🆚 Choose Cloud Sync when: Multiple forests, high availability needed, simpler management

💚 Monitor with Microsoft Entra Connect Health

  • Monitors:
    • Azure AD Connect sync
    • AD FS infrastructure
    • AD DS domain controllers
  • Alerts: Email notifications for issues
  • Reports:
    • Sync errors
    • Performance metrics
    • Usage analytics
  • Requires: Health agent installed on servers

🔧 Troubleshoot Synchronization

  • Common issues:
    • Duplicate attributes
    • Invalid characters
    • Sync errors
    • Connectivity issues
  • Tools:
    • Synchronization Service Manager
    • Synchronization Rules Editor

  • Sync error reports: Available in Azure portal

▼ Implement and Manage Authentication

🔑 Authentication Methods

  • Password Hash Sync (PHS):
    • Hash of password hash synced to Azure AD
    • Most common and recommended
    • Enables leaked credential detection
  • Pass-through Authentication (PTA):
    • Passwords validated against on-premises AD
    • Passwords never in cloud
    • Requires agent installation
  • Federation (AD FS):
    • Most complex option
    • Supports smart cards
    • Requires AD FS infrastructure
  • Passwordless:
    • Windows Hello for Business
    • FIDO2 security keys
    • Microsoft Authenticator app
✅ Recommended: PHS + Seamless SSO for best security and user experience

🔄 Self-Service Password Reset (SSPR)

  • Benefits: Reduces helpdesk calls, empowers users
  • Registration:
    • Users register authentication methods
    • Can require at time of first sign-in
    • Periodic re-registration
  • Authentication methods:
    • Mobile app notification
    • Mobile app code
    • Email
    • Mobile phone (SMS/call)
    • Office phone
    • Security questions
  • Writeback: Sync password changes to on-premises AD
  • Licenses required: Azure AD Premium P1 or P2
# Enable SSPR registration at sign-in Set-MgPolicyAuthorizationPolicy -RegistrationEnforcement @{ EnableRegistrationForSelfService = $true }

🛡️ Microsoft Entra Password Protection

  • Global banned password list: Microsoft-maintained list
  • Custom banned password list: Organization-specific terms
  • Fuzzy matching: Detects variations (e.g., P@ssw0rd)
  • Modes:
    • Audit mode - Logs only
    • Enforced mode - Blocks weak passwords
  • On-premises protection: DC agent + Proxy service

🔍 Investigate Authentication Issues

  • Sign-in logs:
    • Interactive sign-ins
    • Non-interactive sign-ins
    • Service principal sign-ins
    • Managed identity sign-ins
  • Error codes: Diagnostic information for failures
  • Troubleshooting tools:
    • Sign-in diagnostics
    • Azure AD Connect troubleshooter

▼ Implement and Manage Secure Access

🎯 Plan for Identity Protection

  • Risk-based Conditional Access
  • Identity governance
  • Zero Trust principles
  • Requires: Azure AD Premium P2

🚨 Microsoft Entra ID Protection

  • User risk:
    • Leaked credentials
    • Azure AD threat intelligence
    • Unfamiliar sign-in properties
  • Sign-in risk:
    • Anonymous IP address
    • Atypical travel
    • Malware-linked IP
    • Suspicious inbox manipulation rules
    • Password spray
  • Risk levels: Low, Medium, High
  • Policies:
    • User risk policy
    • Sign-in risk policy
    • MFA registration policy
  • Remediation:
    • Require password change
    • Require MFA
    • Block access

📋 Conditional Access Policies

  • Assignments:
    • Users and groups
    • Cloud apps or actions
    • Conditions (location, device, risk, etc.)
  • Conditions:
    • Sign-in risk
    • Device platform (iOS, Android, Windows, macOS)
    • Location (IP ranges, countries)
    • Client apps
    • Device state (compliant, hybrid joined)
  • Access controls:
    • Block access
    • Grant access with requirements:
      • Require MFA
      • Require compliant device
      • Require hybrid Azure AD joined device
      • Require approved client app
      • Require app protection policy
    • Session controls (sign-in frequency, persistent browser session)
  • Policy modes:
    • Report-only - Log but don't enforce
    • On - Enforce policy
    • Off - Disabled
💡 Best Practice: Start with report-only mode, analyze impact, then enable

🔐 Multifactor Authentication (MFA)

  • Methods:
    • Microsoft Authenticator app (push notification or code)
    • SMS to mobile phone
    • Voice call to mobile or office phone
    • OATH hardware tokens
    • OATH software tokens
    • FIDO2 security keys
  • Configuration locations:
    • Conditional Access policies (preferred)
    • Per-user MFA (legacy)
    • Security defaults (basic protection)
  • Remember MFA: Configure trusted device duration
  • Fraud alerts: Users can report fraudulent attempts

4. Manage Compliance using Microsoft Purview (10-15%)

▼ Information Protection and Data Lifecycle Management

🏷️ Sensitive Information Types

  • Built-in types:
    • Credit card numbers
    • Social Security Numbers
    • Passport numbers
    • Bank account numbers
    • 100+ types available
  • Custom types:
    • Keywords and keyword lists
    • Regular expressions (regex)
    • Dictionary-based
    • Proximity rules
    • Confidence levels
  • Exact Data Match (EDM):
    • Based on database of sensitive values
    • More accurate matching
    • Reduces false positives
# Create custom sensitive info type with regex New-DlpSensitiveInformationType -Name "Employee ID" ` -Description "Custom employee ID format" ` -Regex "EMP-[0-9]{6}"

📝 Retention Labels and Policies

  • Retention labels:
    • Applied to individual items (emails, documents)
    • Can be applied manually or automatically
    • Moves with the content
    • Supports multi-stage review
  • Retention policies:
    • Applied to locations (mailboxes, sites, Teams)
    • Automatic application
    • Retention settings:
      • Retain only
      • Delete only
      • Retain then delete
  • Locations:
    • Exchange (email and public folders)
    • SharePoint sites
    • OneDrive accounts
    • Microsoft 365 Groups
    • Teams chats and channel messages
    • Yammer messages
  • Preservation Lock: Prevents policy modification/deletion

🔒 Sensitivity Labels

  • Label settings:
    • Encryption (RMS protection)
    • Content marking (header, footer, watermark)
    • Container protection (Teams, Groups, Sites)
    • Auto-labeling
  • Encryption options:
    • Assign permissions now
    • Let users assign permissions
    • Remove encryption
  • Scope:
    • Files and emails
    • Meetings
    • Groups and sites
    • Schematized data assets
  • Label policies:
    • Publish to users and groups
    • Default label
    • Mandatory labeling
    • Require justification for downgrade
  • Auto-labeling:
    • Based on sensitive info types
    • Trainable classifiers
    • Simulation mode available

📈 Monitor Label Usage
